# ADR 0063：隔离草稿 envelope 版本兼容

- 状态：Accepted
- 日期：2026-09-11

## 背景

隔离草稿是可被用户和智能体编辑的持久化中间产物。随着字段增加，读取和重写必须既能兼容旧文件，也不能在覆盖写时删除未知字段或新的派生数据。

## 决策

隔离草稿 envelope 使用明确的 `schema_version` 字段。当前写入版本为 2，基本形状为：

```json
{
  "schema_version": 2,
  "kind": "...",
  "episode": 1,
  "meta": {},
  "violations": [],
  "content": {}
}
```

读取缺失版本的文件按 v1 解释，并在内存中迁移到当前形状。高于当前版本的文件拒绝读取并返回明确的版本错误；低于已支持版本或非整数版本按损坏信封处理。迁移只负责版本形状兼容，不参与业务内容校验。

重写草稿时保留原 envelope 中未识别的顶层字段，调用方显式传入的扩展字段覆盖同名旧值，标准字段由本次写入重新生成。这样刷新违约报告、晋升失败或取回编辑草稿都不会丢失未知字段和新增派生数据。

坏 JSON 和既有的错误 envelope 继续按不可读草稿处理：读取返回空结果，但文件存在状态仍然阻塞审阅门和后续生成。未来版本是唯一需要向调用方明确暴露的版本兼容错误。

## 后果

- 不需要数据库迁移；兼容逻辑位于草稿文件读写边界。
- 新字段可以先被新版本写入，再由旧业务字段逻辑安全地保留。
- 未来 schema 需要新增迁移函数时，不必把版本分支散落到业务校验代码中。
